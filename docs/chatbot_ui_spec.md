# Chatbot UI Specification — Newsletter Pipeline Assistant

**Status:** Design / pre-implementation  
**Created:** 2026-05-06  
**Scope:** A new Streamlit application (`run_chatbot_ui.py`) that replaces the batch CLI pipeline with a conversational AI interface. Does not modify any existing agent code.

---

## 1. Goals

| Goal | Detail |
|---|---|
| Conversational pipeline control | Chat with an AI to run any pipeline stage or the full sequence |
| Pipeline health at a glance | See pending item counts at every stage before deciding what to run |
| Sectionizer review & editing | Read, manually edit, or AI-prompt-refine every sectionizer result |
| Full prompt audit trail | Every user prompt, system prompt, and AI response is stored in the DB |

---

## 2. How the Existing Pipeline Is Invoked

Each agent is started via a Google ADK `Runner` with an `InMemorySessionService`. The pattern used in every `run_*.py` launcher is:

```python
session_service = InMemorySessionService()
await session_service.create_session(app_name=APP_NAME, user_id=USER_ID, session_id=SESSION_ID)
runner = Runner(agent=<agent_instance>, app_name=APP_NAME, session_service=session_service)
prompt = types.Content(role="user", parts=[types.Part(text="<instruction text>")])
async for event in runner.run_async(user_id=USER_ID, session_id=SESSION_ID, new_message=prompt):
    ...
```

The Streamlit UI must run each agent inside `asyncio.run()` or via `asyncio.get_event_loop().run_until_complete()` since Streamlit is synchronous. Streaming output from the runner should be captured incrementally and displayed in a Streamlit `st.empty()` placeholder.

Available agent instances (imported from existing modules — do not re-create):

| Stage | Import path | Instance name |
|---|---|---|
| Hoarder | `agents.hoarder.agent` | `root_agent` (rename to `hoarder_agent` at import) |
| Screener (hosted) | `agents.screener.agent_hosted` | `file_metadata_screening_agent` |
| Screener (ollama) | `agents.screener.agent` | `file_metadata_screening_agent` |
| Standardizer | `agents.standardizer.agent` | `standardizer_agent` |
| Sectionizer | `agents.sectionizer.agent` | `sectionizer_agent` |
| Newsletter Generator | `agents.newsletter_generator.agent` | `newsletter_generator_agent` |

The `root_agent` in `agent.py` is a `SequentialAgent` wrapper. For the UI, invoke individual agents directly rather than through `root_agent`.

## 4. New Database Tables

Add to `db/standardizer_db.py`. All new tables are created inside `ensure_standardizer_schema()` via `Base.metadata.create_all(engine)`.

### 4.1 `ui_chat_sessions`

One row per Streamlit chat session.

```sql
CREATE TABLE ui_chat_sessions (
    session_id      TEXT    PRIMARY KEY,   -- UUID, generated by UI at session start
    title           TEXT,                  -- auto-generated or user-set title
    created_at      TEXT    NOT NULL,
    updated_at      TEXT    NOT NULL
);
```

ORM class: `UiChatSession`

### 4.2 `ui_chat_messages`

Append-only log of every message in every chat session.

```sql
CREATE TABLE ui_chat_messages (
    message_id      INTEGER PRIMARY KEY AUTOINCREMENT,
    session_id      TEXT    NOT NULL REFERENCES ui_chat_sessions(session_id),
    role            TEXT    NOT NULL,      -- 'user' | 'assistant' | 'tool_result'
    content         TEXT    NOT NULL,      -- raw message text or JSON for tool results
    tool_name       TEXT,                  -- populated when role = 'tool_result'
    created_at      TEXT    NOT NULL
);
```

ORM class: `UiChatMessage`

### 4.3 `ui_prompts`

Single canonical table for every prompt sent to any LLM from the UI. Covers chatbot turns, sectionizer refinements, and system prompts rendered for each call.

```sql
CREATE TABLE ui_prompts (
    prompt_id           INTEGER PRIMARY KEY AUTOINCREMENT,
    session_id          TEXT,              -- NULL for non-chatbot prompts
    prompt_type         TEXT    NOT NULL,  -- see §4.3a
    target_type         TEXT,              -- 'sectionizer_output' | 'pipeline_run' | NULL
    target_id           INTEGER,           -- FK value matching target_type (e.g. sectionizer_output_id)
    model               TEXT    NOT NULL,  -- e.g. 'gemini-2.5-flash-lite'
    system_prompt       TEXT,              -- full system/instruction text sent to LLM
    user_prompt         TEXT    NOT NULL,  -- the user-visible prompt text
    response_text       TEXT,             -- raw LLM response (populated after call completes)
    input_tokens        INTEGER,
    output_tokens       INTEGER,
    latency_ms          INTEGER,
    created_at          TEXT    NOT NULL
);
```

ORM class: `UiPrompt`

#### 4.3a `prompt_type` values

| Value | When used |
|---|---|
| `chatbot_turn` | A user message in the main chat interface |
| `chatbot_tool_call` | A tool invocation generated by the chatbot LLM |
| `sectionizer_ai_refinement` | An AI prompt to re-score or rewrite a sectionizer result |
| `sectionizer_system` | The system prompt sent alongside a sectionizer refinement call |

### 4.4 `sectionizer_output_edits`

Stores every manual or AI-driven change to a sectionizer result. Does not overwrite `sectionizer_outputs`; the original is always preserved.

```sql
CREATE TABLE sectionizer_output_edits (
    edit_id                 INTEGER PRIMARY KEY AUTOINCREMENT,
    sectionizer_output_id   INTEGER NOT NULL REFERENCES sectionizer_outputs(sectionizer_output_id),
    edit_type               TEXT    NOT NULL,   -- 'manual' | 'ai_refinement'
    prompt_id               INTEGER REFERENCES ui_prompts(prompt_id),  -- NULL for manual edits
    section_name            TEXT,               -- which section was edited (NULL = whole output)
    field_name              TEXT,               -- 'newsletter_title' | 'summary' | 'summary_facts' | 'passes_threshold' | 'full_json'
    original_value          TEXT,               -- the value before this edit
    edited_value            TEXT    NOT NULL,   -- the new value (serialized; JSON arrays for summary_facts)
    editor_notes            TEXT,               -- optional free-text note from user
    accepted                INTEGER NOT NULL DEFAULT 1,  -- 1=accepted, 0=rejected (for AI suggestions)
    created_at              TEXT    NOT NULL
);
```

ORM class: `SectionizerOutputEdit`

## 5. Pipeline Status Queries (`ui/db_status.py`)

All queries run against `data/standardizer.db` using `session_scope()`. Return plain dicts for easy display.

```python
def get_pipeline_status() -> dict:
    """Return pending item counts at each stage."""
    # hoarder_pending: hoarder_outputs added since last screener run
    #   → COUNT(*) FROM hoarder_outputs WHERE screened_at IS NULL
    # screener_pending: screened_files not yet standardized
    #   → COUNT(*) FROM screened_files WHERE is_selected=1 AND processed_at IS NULL
    # standardizer_pending: documents not yet sectionized
    #   → COUNT(*) FROM documents d
    #       WHERE NOT EXISTS (SELECT 1 FROM sectionizer_outputs so WHERE so.doc_id = d.doc_id)
    #       AND d.text_content IS NOT NULL AND TRIM(d.text_content) <> ''
    # sectionizer_pending: sectionizer_outputs not yet in any newsletter run
    #   → COUNT(*) FROM sectionizer_outputs so
    #       WHERE NOT EXISTS (SELECT 1 FROM newsletter_run_sectionizer_outputs nr WHERE nr.sectionizer_output_id = so.sectionizer_output_id)
    # last_newsletter_run: MAX(created_at) FROM newsletter_runs
    return {
        "hoarder_pending": int,
        "screener_pending": int,
        "standardizer_pending": int,
        "sectionizer_pending": int,
        "last_newsletter_run": str | None,
        "total_hoarder_outputs": int,
        "total_documents": int,
        "total_sectionizer_outputs": int,
        "total_newsletter_runs": int,
    }
```

## 6. Chatbot Design (`ui/chatbot_page.py`, `ui/chatbot_llm.py`)

### 6.1 LLM

Use the same Gemini model as the sectionizer (`SECTIONIZER_GEMINI_MODEL` env var, default `gemini-2.5-flash-lite`) via `google.genai` client. Alternatively, support Claude via `CHATBOT_LLM_PROVIDER` env var (`gemini` | `claude`). For Claude, use `anthropic` SDK.

### 6.2 System Prompt

The chatbot system prompt is rendered once per session and stored as a `ui_prompts` row with `prompt_type='sectionizer_system'` on first use.

```
You are a newsletter pipeline assistant. You help the user run and monitor a document 
processing pipeline with these stages in order:

  hoarder → screener → standardizer → sectionizer → newsletter_generator

You have tools to check pipeline status, run individual stages, and run the full pipeline.
When the user asks about pending items or pipeline health, call get_pipeline_status() first.
When the user wants to run a stage, confirm which stage and call the appropriate run_* tool.
For screener, ask about backend preference (hosted or ollama) if not specified.
Be concise. Show counts and stage names clearly.
```

### 6.3 Chatbot Tools

Define as function schemas for the LLM. Each tool maps to a function in `ui/pipeline_runner.py`.

| Tool name | Parameters | Returns | Side effect |
|---|---|---|---|
| `get_pipeline_status` | none | dict (§5 shape) | none |
| `run_hoarder` | none | `{success, items_added, error?}` | invokes hoarder ADK runner |
| `run_screener` | `backend: "hosted"\|"ollama"` | `{success, items_screened, error?}` | invokes screener ADK runner |
| `run_standardizer` | none | `{success, docs_created, error?}` | invokes standardizer ADK runner |
| `run_sectionizer` | none | `{success, docs_sectionized, error?}` | invokes sectionizer ADK runner |
| `run_newsletter_generator` | none | `{success, run_id?, error?}` | invokes newsletter generator ADK runner |
| `run_full_pipeline` | `backend: "hosted"\|"ollama"` | `{stages: list[stage_result]}` | runs all stages in sequence |
| `get_sectionizer_summary` | `limit: int = 10` | list of recent sectionizer output summaries | none |

### 6.4 Tool Call / Response Loop

```
user message
    → store in ui_chat_messages (role='user') and ui_prompts (prompt_type='chatbot_turn')
    → send to LLM with tool definitions
    → LLM returns text or tool_call
        if tool_call:
            → store in ui_prompts (prompt_type='chatbot_tool_call')
            → execute tool in pipeline_runner.py
            → store result in ui_chat_messages (role='tool_result')
            → send result back to LLM
            → LLM returns final text response
        → store assistant response in ui_chat_messages (role='assistant')
        → display in chat bubble
```

### 6.5 Streamlit Session State Keys

| Key | Type | Description |
|---|---|---|
| `chat_session_id` | str | UUID for current session, persisted in `ui_chat_sessions` |
| `chat_messages` | list[dict] | In-memory message history for `st.chat_message` rendering |
| `pipeline_status_cache` | dict | Cached result of `get_pipeline_status()`, refreshed on demand |
| `active_page` | str | Current sidebar page |
| `sectionizer_selected_output_id` | int\|None | Output being reviewed in editor |

## 7. Pipeline Runner (`ui/pipeline_runner.py`)

Wraps each agent invocation in a synchronous helper by running the async ADK pattern inside `asyncio.run()`.

```python
def run_agent_sync(agent, app_name: str, prompt_text: str) -> tuple[bool, str]:
    """
    Run an ADK agent synchronously. Returns (success, output_text).
    Creates a fresh InMemorySessionService and Runner each call.
    Collects all event text parts into a single string.
    Raises on unhandled exceptions; caller stores the error in ui_prompts.
    """
```

Each public `run_*` function:
1. Calls `run_agent_sync(agent, app_name, prompt_text)`
2. Stores the invocation in `ui_prompts` (system prompt + user prompt + response)
3. Returns a structured result dict

Streaming display: for long-running stages, use `st.empty()` and update it inside a thread running the async event loop. The ADK runner yields events — each event's text parts are appended to the placeholder in real time.

## 8. Sectionizer Editor (`ui/sectionizer_editor_page.py`)

### 8.1 List View

Displays all `sectionizer_outputs` rows joined with `documents` and `sectionizer_categories`. Columns:

- Doc ID
- Source path (truncated)
- Primary category (from `sectionizer_categories.name` via `category_id`)
- Match count
- Has edits (bool — any row in `sectionizer_output_edits`)
- Run timestamp
- Action: "Open Editor" button

Filters: category dropdown, match count range, run date range, "edited only" toggle.

### 8.2 Detail View

Opened when a row is selected. Split into three sub-panels:

#### Panel A — Document Info (read-only)
- `source_path`
- `author`
- `document_summary` (from `output_json`)
- Link to original document if local path

#### Panel B — Section Evaluations (scrollable)

For each entry in `section_evaluations` from `output_json`:

- Section name + score badge (color-coded: green ≥ min_score, red < min_score)
- `passes_threshold` indicator
- `newsletter_title`
- `summary`
- `summary_facts` as a bullet list
- Per-rule scores table: rule text, score, reason, fact

#### Panel C — Edit Controls (tabbed)

**Tab 1: Manual Edit**

For the selected section evaluation, show editable fields:

| Field | Widget |
|---|---|
| `newsletter_title` | `st.text_input` |
| `summary` | `st.text_area` |
| `summary_facts` | `st.data_editor` (list of strings) |
| `passes_threshold` override | `st.checkbox` |
| Editor notes | `st.text_area` |

On "Save":
1. Read original values from `output_json`
2. For each changed field, insert one row in `sectionizer_output_edits` with `edit_type='manual'`
3. Show confirmation

**Tab 2: AI Refinement**

```
Refinement prompt: [st.text_area]  e.g. "Make the summary more concise and executive-friendly"
Target section: [st.selectbox of sections that passed threshold]
[ Run AI Refinement ]
```

On submit:
1. Build a system prompt (see §8.3)
2. Build a user prompt containing the current section output JSON + refinement instruction
3. Store both in `ui_prompts` (`prompt_type='sectionizer_ai_refinement'`, `target_type='sectionizer_output'`, `target_id=sectionizer_output_id`)
4. Call the LLM; store response in `ui_prompts.response_text`
5. Parse the LLM response as JSON (same shape as a single section evaluation)
6. Show a side-by-side diff: original vs. proposed
7. User clicks "Accept" or "Reject":
   - Accept: insert rows in `sectionizer_output_edits` (`edit_type='ai_refinement'`, `prompt_id=<id>`, `accepted=1`)
   - Reject: insert row with `accepted=0`

**Tab 3: Edit History**

Table of all `sectionizer_output_edits` rows for this `sectionizer_output_id`:
- Timestamp, edit type, field, original value, edited value, accepted flag, prompt link

### 8.3 AI Refinement System Prompt

Stored in `ui_prompts` with `prompt_type='sectionizer_system'` alongside each refinement call.

```
You are an editorial assistant improving newsletter section summaries.
You will receive a JSON object representing one section evaluation for a document.
The user will give you a refinement instruction.
Return ONLY a valid JSON object with the same structure as the input, with the 
requested fields improved. Do not add or remove top-level keys.
Preserve factual accuracy — do not introduce information not present in the original.
```

## 14. Constraints and Decisions

- **No modification to existing agent code.** All agent modules are imported and used as-is.
- **Each agent run creates a fresh `InMemorySessionService`.** State does not persist across runs. The DB is the only cross-run store.
- **Streamlit reruns on every interaction.** Use `st.session_state` to hold in-memory chat history between reruns. DB is the persistence layer.
- **Async agents in a sync Streamlit context.** Use `asyncio.run()` inside each `run_*` function. Do not use `asyncio.get_event_loop()` in Streamlit >= 1.20 (it raises in some environments); prefer `asyncio.run()`.
- **Sectionizer edits are non-destructive.** `sectionizer_outputs` is never updated. Edits live entirely in `sectionizer_output_edits`. Consumers that need the edited value must join both tables and prefer the latest accepted edit.
- **Backup files** (`config copy.json`, `prompt_template copy*.md`, etc.) are left in place and ignored by all new code.
- **`run_newsletter_generator.py` and `run_observability_dashboard.py`** do not exist yet; the UI does not depend on them.
